# Board Configuration

## Configuration Structure

The complete configuration is defined in the `BoardConfig` struct:

```solidity
struct BoardConfig {
    string version;
    Metadata boardMetadata;
    address owner;                                      // Board owner address
    address underlyingToken;                           // ERC20 token address
    AcceptanceCriteria acceptanceCriteria;             // Who can accept and threshold rules
    uint256 maxLockIntervals;                          // Max lock duration in intervals
    uint256 lockInterval;                              // Time unit for locks (seconds)
    uint256 decayCurveType;                           // 0=linear, 1=exponential
    uint256[] decayCurveParameters;                    // Curve params (must be length 1)
    uint256 inactivityTimeout;                         // Seconds before initiative can expire
    ParticipantRequirements proposerRequirements;      // Who can propose
    ParticipantRequirements supporterRequirements;     // Who can support
    uint256 releaseLockDuration;                       // Timelock after acceptance
    uint256 boardOpenAt;                              // Unix timestamp for opening
    uint256 boardClosedAt;                            // Unix timestamp for closing (0 = never)
}
```

## Acceptance Criteria

The `AcceptanceCriteria` struct controls who can accept initiatives and under what conditions:

```solidity
enum AcceptancePermissions {
    Permissionless,  // Anyone can accept if threshold is met
    OnlyOwner        // Only the board owner can accept
}

enum ThresholdOverride {
    None,            // Everyone (including owner) must meet threshold
    OnlyOwner        // Owner can bypass threshold requirement
}

struct AcceptanceCriteria {
    AcceptancePermissions permissions;
    ThresholdOverride thresholdOverride;
    uint256 thresholdPercentTotalSupplyWAD;  // Percentage of total supply (in WAD)
    uint256 minThreshold;                     // Minimum fixed threshold
}
```

### Permission Combinations

| permissions | thresholdOverride | Behavior |
|-------------|-------------------|----------|
| `OnlyOwner` | `None` | Only owner can accept, owner must meet threshold |
| `OnlyOwner` | `OnlyOwner` | Only owner can accept, owner can bypass threshold |
| `Permissionless` | `None` | Anyone can accept if threshold met, owner also needs threshold |
| `Permissionless` | `OnlyOwner` | Owner can always accept; others need threshold met |

### Threshold Calculation

The effective acceptance threshold is calculated as:

```solidity
threshold = max(
    totalSupply * thresholdPercentTotalSupplyWAD / 1e18,
    minThreshold
)
```

**Requirements:**

- At least one of `thresholdPercentTotalSupplyWAD` or `minThreshold` must be non-zero
- `thresholdPercentTotalSupplyWAD` must be less than 100% (< 1e18)

### Example Configurations

**Owner-controlled board (default):**

```solidity
AcceptanceCriteria({
    permissions: AcceptancePermissions.OnlyOwner,
    thresholdOverride: ThresholdOverride.OnlyOwner,
    thresholdPercentTotalSupplyWAD: 0,
    minThreshold: 100_000 * 1e18  // 100k tokens
})
```

**Community-driven board:**

```solidity
AcceptanceCriteria({
    permissions: AcceptancePermissions.Permissionless,
    thresholdOverride: ThresholdOverride.None,
    thresholdPercentTotalSupplyWAD: 5e16,  // 5% of total supply
    minThreshold: 50_000 * 1e18            // At least 50k tokens
})
```

**Hybrid board (owner can fast-track):**

```solidity
AcceptanceCriteria({
    permissions: AcceptancePermissions.Permissionless,
    thresholdOverride: ThresholdOverride.OnlyOwner,
    thresholdPercentTotalSupplyWAD: 10e16,  // 10% of total supply
    minThreshold: 100_000 * 1e18            // At least 100k tokens
})
```

## Core Parameters

### owner

- **Type:** `address`
- **Purpose:** Address that controls the board (can accept initiatives, close board, etc.)
- **Requirement:** Must not be `address(0)` (i.e. ownerless boards are not allowed)
- **Suggestion:** Use a multisig or DAO-controlled address for trustless operation

### underlyingToken

- **Type:** `address`
- **Purpose:** The token used for signaling and voting weight
- **Requirement:** Must be a valid ERC20 token address
- **Token Types:**
  - Standard ERC20: Works with all eligibility types except `MinBalanceAndDuration`
  - ERC20Votes: Required for `MinBalanceAndDuration` eligibility (checkpoint support)

### lockInterval

- **Type:** `uint256` (seconds)
- **Purpose:** Time unit for lock durations and decay calculations
- **Requirement:** Must be > 0

### maxLockIntervals

- **Type:** `uint256` (number of intervals)
- **Purpose:** Maximum duration users can lock tokens, represented as a number of intervals
- **Requirement:** Must be > 0
- **Note:** For example, if `lockInterval` is set to 86400 (1 day), then a `maxLockIntervals` of 365 would allow for a maximum lock duration of 365 days

### decayCurveType

- **Type:** `uint256`
- **Purpose:** How weight decays over time
- **Requirement:** Must be a valid option (currently only 2 types are supported):
- **Options:**
  - `0` - Linear decay: Weight decreases steadily
  - `1` - Exponential decay: Weight decreases at accelerating rate

### decayCurveParameters

- **Type:** `uint256[]`
- **Purpose:** Parameters for the decay curve
- **Requirement:** Array length must match what is expected based on the chosen decay curve type
- **Linear Decay (Type 0):**
  - Parameter: Decay rate (1e18 = 1:1 linear)
- **Exponential Decay (Type 1):**
  - Parameter: Decay multiplier per interval

### inactivityTimeout

- **Type:** `uint256` (seconds)
- **Purpose:** Duration of inactivity after which an initiative can be expired by the owner
- **Default:** 60 days (5,184,000 seconds)
- **Note:** Activity is tracked via the `lastActivity` timestamp, which updates when the initiative is created or when any supporter locks tokens

### releaseLockDuration

- **Type:** `uint256` (seconds)
- **Purpose:** Board-level timelock parameter that prevents immediate token redemption after an initiative is accepted
- **Mechanism:** Adds an additional commitment period after acceptance, ensuring supporters remain locked even after the initiative reaches the acceptance threshold
- **Requirement:** Set to `0` for immediate redemption upon acceptance, or specify duration in seconds for delayed release
- **Redemption Logic:** Tokens can be redeemed when `acceptanceTimestamp + releaseLockDuration <= block.timestamp` or once the supporter's lockup duration is completed
- **Override:** Board cancellation or initiative expiration bypasses this timelock, allowing immediate redemption regardless of the configured duration

### boardOpenAt

- **Type:** `uint256` (Unix timestamp)
- **Purpose:** Fair launch mechanism - board doesn't accept proposals until this time
- **Values:**
  - `0` - Board stays closed until explicitly opened via `setBoardOpenAt`
  - `block.timestamp + 1 hours` - Opens 1 hour from deployment
  - Specific timestamp for scheduled launch

### boardClosedAt

- **Type:** `uint256` (Unix timestamp)
- **Purpose:** Timestamp when the board closes for new activity
- **Values:**
  - `0` - Board never closes automatically
  - Specific timestamp for scheduled closure

## Validation & Errors

| Error | Condition | Fix |
|-------|-----------|-----|
| `SignalsFactory_ZeroAddressOwner` | Owner is address(0) | Provide valid owner address |
| `Signals_InvalidArguments` | Token is address(0) | Provide valid token address |
| `Signals_InvalidArguments` | Both thresholds are 0 | Set at least one threshold > 0 |
| `Signals_InvalidArguments` | Percentage threshold >= 100% | Set thresholdPercentTotalSupplyWAD < 1e18 |
| `Signals_InvalidArguments` | Max intervals is 0 | Set max intervals > 0 |
| `Signals_InvalidArguments` | Lock interval is 0 | Set lock interval > 0 |
| `Signals_InvalidArguments` | Invalid decay curve type | Use type 0 or 1 |
| `Signals_InvalidArguments` | boardClosedAt < boardOpenAt | Ensure close time is after open time |
