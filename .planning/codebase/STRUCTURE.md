# Codebase Structure

## Directory Purposes

**apps/interface:**
- Purpose: React/Next.js frontend application for the Signals protocol
- Contains: Pages, components, hooks, contexts, stores, configuration, styling
- Key files: `src/app/layout.tsx` (root layout), `src/app/page.tsx` (redirect), `src/app/[network]/[boardAddress]` (board pages)

**apps/interface/src/app:**
- Purpose: Next.js App Router pages and API routes
- Contains: Route segments, API endpoints, global styling
- Structure: `[network]/[boardAddress]` for dynamic board pages, `api/edge-city/` for Edge City integration

**apps/interface/src/components:**
- Purpose: React component library for interface
- Contains: Functional components organized by type (containers, dialogs, drawers, inputs, web3, edge-city)
- Key subdirs: `containers/boards`, `containers/initiatives`, `dialogs`, `drawers/propose-initiative-drawer`, `web3` (wallet components)

**apps/interface/src/contexts:**
- Purpose: React Context providers for application state
- Contains: ThemeContext, ChainProvider, WalletProvider, SignalsContext, IncentivesContext
- Pattern: Each context wraps related state with provider component and custom hook

**apps/interface/src/hooks:**
- Purpose: Custom React hooks for logic extraction
- Contains: Web3 interaction hooks (useBalanceOf, useApproveTokens), network hooks (useNetwork), custom hooks (useAsyncProp, useIsClient)

**apps/interface/src/stores:**
- Purpose: Client-side state management using Zustand
- Contains: useBoardsStore, useInitiativesStore, useLocksStore, useNetworkStore, useRouteStore, useSupportDrawerStore, useRewardsStore
- Pattern: Each store fetches data from indexer GraphQL and caches locally

**apps/interface/src/lib:**
- Purpose: Utility functions and helper libraries
- Contains: Viem clients, GraphQL types, routing helpers, theme utilities, chart calculations, curve math
- Subdirs: `viem/` (publicClient, walletClient), `indexer/` (GraphQL types), `server/` (Edge City client), `__tests__/` (unit tests)

**apps/interface/src/config:**
- Purpose: Application configuration and constants
- Contains: Network definitions, theme config, Web3 config, feature flags, network-specific endpoints
- Key files: `networks.ts`, `network-config.ts`, `theme.ts`, `web3.ts`, `features.ts`, `edge-city.ts`

**apps/indexers:**
- Purpose: Ponder indexer for on-chain data synchronization
- Contains: Event handlers, schema definitions, API routes, utilities
- Key files: `ponder.config.ts` (chain/contract configuration), `ponder.schema.ts` (database schema)

**apps/indexers/src/api:**
- Purpose: REST API endpoints for indexed data queries
- Contains: Handlers for initiatives, locks, bonds, stats queries
- Pattern: Each handler returns filtered data from Ponder database via Drizzle ORM

**apps/protocol/src:**
- Purpose: Core Solidity smart contract implementations
- Contains: Factory, board, voting, locking, incentive, and utility contracts
- Key files: `SignalsFactory.sol`, `ISignals.sol`, `DecayCurves.sol`, `Authorizer.sol`

**apps/sdk/src:**
- Purpose: TypeScript SDK for interacting with Signals protocol
- Contains: GraphQL client wrapper, action definitions, constants, type definitions
- Key files: `sdk.ts` (SignalsSDK class), `clients.ts`, `actions/list-boards.ts`, `actions/get-board.ts`

**packages/abis:**
- Purpose: Generated contract ABI exports from Solidity
- Contains: ABIs for SignalsFactory, Signals, ExperimentToken, etc.
- Generated by: `wagmi generate` from `wagmi.config.ts`

**packages/ui:**
- Purpose: Reusable React UI components
- Contains: Base components (Button, Header, etc.)
- Exported: Via `index.tsx`

**packages/shared:**
- Purpose: Shared TypeScript utilities and helpers
- Contains: Currently empty (index.ts only)
- Usage: Import location for shared logic across apps

**packages/tsconfig:**
- Purpose: Shared TypeScript configuration templates
- Contains: Reusable tsconfig.json definitions

## Key File Locations

**Entry Points:**
- `apps/interface/src/app/layout.tsx`: Root layout with all providers
- `apps/interface/src/app/page.tsx`: Home page redirect to default network
- `apps/indexers/ponder.config.ts`: Indexer configuration and chain setup
- `apps/protocol/src/SignalsFactory.sol`: Factory contract for board creation
- `wagmi.config.ts`: ABI generation configuration

**Configuration:**
- `apps/interface/src/config/network-config.ts`: Network definitions and RPC endpoints
- `apps/interface/src/config/theme.ts`: Typography and color system
- `apps/interface/src/config/features.ts`: Feature flags
- `apps/indexers/ponder.config.ts`: Contract event tracking configuration
- `turbo.json`: Build system task definitions

**Core Logic:**
- `apps/interface/src/contexts/SignalsContext.tsx`: Board state and metadata fetching
- `apps/interface/src/stores/useBoardsStore.ts`: Boards data management
- `apps/interface/src/lib/viem/`: Blockchain RPC client setup
- `apps/indexers/src/api/index.ts`: API routes and GraphQL setup
- `apps/protocol/src/SignalsFactory.sol`: Board factory logic

**Testing:**
- `apps/interface/src/lib/__tests__/`: Jest unit tests for utilities
- `apps/protocol/test/`: Foundry contract tests
- `apps/simulations/`: Protocol simulation and testing environment

## Naming Conventions

**Files:**
- Components: PascalCase (e.g., `ChainProvider.tsx`, `AppSidebar.tsx`)
- Utilities: camelCase (e.g., `routing.ts`, `curves.ts`, `chart.ts`)
- Hooks: camelCase with `use` prefix (e.g., `useBalanceOf.ts`, `useNetwork.ts`)
- Stores: camelCase with `use` prefix (e.g., `useBoardsStore.ts`)
- Test files: Match source with `.test.ts` or `.spec.ts` suffix (e.g., `chart.test.ts`)
- API handlers: `get.{entity}.ts` pattern (e.g., `get.initiatives.ts`, `get.locks.ts`)

**Directories:**
- Feature directories: kebab-case (e.g., `propose-initiative-drawer`, `edge-city`)
- Type/category directories: camelCase or kebab-case (e.g., `components/`, `contexts/`, `containers/`)

## Where to Add New Code

**New Feature (e.g., new page):**
- Primary code: `apps/interface/src/app/[network]/[new-feature]/page.tsx`
- Components: `apps/interface/src/components/containers/[feature-name]/`
- Context if needed: `apps/interface/src/contexts/[FeatureName]Context.tsx`
- Store if needed: `apps/interface/src/stores/use[FeatureName]Store.ts`
- Tests: `apps/interface/src/lib/__tests__/[feature].test.ts` or co-located with component

**New Component/Module:**
- UI Component: `apps/interface/src/components/[category]/ComponentName.tsx`
- Container Component: `apps/interface/src/components/containers/[feature]/ComponentName.tsx`
- Dialog/Drawer: `apps/interface/src/components/dialogs/` or `drawers/[feature]/`

**New Hook:**
- Location: `apps/interface/src/hooks/useCamelCaseName.ts`
- Export from: Directly import or add to hooks barrel if created

**New Utility/Helper:**
- Location: `apps/interface/src/lib/utilityName.ts`
- Subdirectory: `lib/[domain]/utilityName.ts` for domain-specific utilities

**New API Endpoint (Indexer):**
- Location: `apps/indexers/src/api/get.[entity].ts`
- Register in: `apps/indexers/src/api/index.ts` with route definition

**New Store:**
- Location: `apps/interface/src/stores/use[DomainName]Store.ts`
- Pattern: Follow Zustand pattern in `useBoardsStore.ts`

**New Smart Contract:**
- Location: `apps/protocol/src/[ContractName].sol` or `apps/signals-token-factory/src/`
- Tests: `apps/protocol/test/[ContractName].t.sol`

## Special Directories

**node_modules:**
- Purpose: NPM dependencies (monorepo uses pnpm)
- Generated: Yes
- Committed: No (.gitignore)

**.next:**
- Purpose: Next.js build output directory
- Generated: Yes (by `pnpm build`)
- Committed: No

**.ponder:**
- Purpose: Ponder indexer cache and database
- Generated: Yes
- Committed: No

**broadcast/ (protocol and token-factory):**
- Purpose: Foundry deployment transaction records
- Generated: Yes (by forge script)
- Committed: Yes (for deployment tracking)

**.planning/codebase/:**
- Purpose: Codebase analysis documents (ARCHITECTURE.md, STRUCTURE.md, etc.)
- Generated: Yes (by GSD mapper)
- Committed: Yes
