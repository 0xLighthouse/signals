<objective>
Thread curve_type as a first-class parameter from generate_scenario() through the simulation runner, cadCAD SUFs, metrics layer, and pipeline.

Purpose: curve_type is currently hardcoded to 'sqrt' everywhere. Phase 10's sweep engine needs to vary curve_type across sweep cells. Without proper threading, generate_scenario(curve_type='log') would produce events using log curves in cadCAD but the metrics layer would silently re-compute weights using sqrt — corrupting all Gini/ENP/Nakamoto/concentration metrics.

Output: curve_type flows correctly from generate_scenario() → cadCAD M params → suf_tallies → compute_signals_weight, AND through metrics layer via _add_signals_weight_column. Pipeline orchestrates both paths. All 147+ tests pass.
</objective>
