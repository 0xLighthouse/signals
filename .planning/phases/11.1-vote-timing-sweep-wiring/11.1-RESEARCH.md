# Phase 11.1: Wire vote_timing Through Sweep - Research

**Researched:** 2026-02-28
**Domain:** Python dataclass extension, sweep engine wiring, itertools.product cartesian axis
**Confidence:** HIGH

## Summary

Phase 11.1 closes GAP-1 identified in the v3.0 milestone audit: `VoteTimingConfig` exists in `factory.py` and is already accepted by `generate_scenario()`, but the sweep engine (`sweep.py`) never passes it. `SweepCell` has no `vote_timing` field and `_run_cell()` never injects a `vote_timing` kwarg into the `generate_scenario()` call. This phase is a focused, surgical wiring task — no new abstractions are required.

The pattern to follow is exact: `mc_dist` was wired the same way in Phase 10.1 (INT-01). `SweepConfig` gained an `mc_dists: list[AllocationDistribution] | None = None` field; `SweepCell` gained `mc_dist: AllocationDistribution | None = None`; `_enumerate_cells()` added `mc_dist_values` to the `itertools.product` call; and `_run_cell()` injected `kwargs['mc_dist'] = cell.mc_dist` when non-None. This phase replicates that pattern exactly for `vote_timing`.

The scope is narrow: three dataclass fields (one on `SweepConfig`, one on `SweepCell`, one bookkeeping update to `_make_failed_row`), one axis addition to `_enumerate_cells()`, one kwarg injection in `_run_cell()`, and one TOML loader update to optionally parse `vote_timings`. Test coverage should follow the `mc_dists` test pattern in `test_sweep.py`, adding a distinct-results integration test as the new element required by Success Criterion 4.

**Primary recommendation:** Mirror the mc_dist wiring pattern precisely. Do not invent new abstractions. The entire change fits in `sweep.py` with no other files requiring modification.

### Pattern 1: mc_dist Wiring (canonical precedent to replicate)

**What:** Add an optional cartesian axis to the sweep engine by adding a field to `SweepConfig`, a field to `SweepCell`, an axis value list to `_enumerate_cells`, and a conditional kwarg injection in `_run_cell`.

**When to use:** Every time a new generate_scenario() optional parameter becomes a sweep axis.

**Example (existing mc_dist code to mirror):**
```python
# Source: apps/simulations/src/backtesting/sweep.py (lines 64, 85, 124-131, 334-336)

# SweepConfig field (line 64)
mc_dists: list[AllocationDistribution] | None = None

# SweepCell field (line 85)
mc_dist: AllocationDistribution | None = None

# _enumerate_cells axis injection (lines 124-131)
mc_dist_values = config.mc_dists if config.mc_dists else [None]
combos = itertools.product(
    config.curve_types,
    config.alphas,
    config.lock_profiles,
    config.allocation_strategies,
    mc_dist_values,
)
for cell_id, (curve_type, alpha, lock_profile, allocation_strategy, mc_dist) in enumerate(combos):
    cells.append(SweepCell(..., mc_dist=mc_dist))

# _run_cell injection (lines 334-336)
if cell.mc_dist is not None:
    kwargs['mc_dist'] = cell.mc_dist
```

**Target (vote_timing equivalent):**
```python
# SweepConfig field
vote_timings: list[VoteTimingConfig] | None = None

# SweepCell field
vote_timing: VoteTimingConfig | None = None

# _enumerate_cells axis injection
vote_timing_values = config.vote_timings if config.vote_timings else [None]
combos = itertools.product(
    config.curve_types,
    config.alphas,
    config.lock_profiles,
    config.allocation_strategies,
    mc_dist_values,
    vote_timing_values,
)
for cell_id, (..., mc_dist, vote_timing) in enumerate(combos):
    cells.append(SweepCell(..., mc_dist=mc_dist, vote_timing=vote_timing))

# _run_cell injection
if cell.vote_timing is not None:
    kwargs['vote_timing'] = cell.vote_timing
```

### Pattern 2: _make_failed_row bookkeeping

`_make_failed_row` carries the cell's grid parameters. It currently records `mc_dist_label` but not `vote_timing`. Add `vote_timing_label` for schema consistency:

```python
# Source: apps/simulations/src/backtesting/sweep.py _make_failed_row (line 274)
'mc_dist_label': repr(cell.mc_dist) if cell.mc_dist is not None else None,

# Add (analogous):
'vote_timing_label': repr(cell.vote_timing) if cell.vote_timing is not None else None,
```

The successful row in `_run_cell` return dict should also include `vote_timing_label` for schema consistency.

### Pattern 3: TOML loader for vote_timings

`load_sweep_config` must optionally parse `vote_timings` from TOML. Since `VoteTimingConfig` is a simple dataclass with `early` and `mid` floats, the TOML representation is a list of inline tables or a table array:

```toml
[[sweep.vote_timings]]
early = 0.30
mid = 0.40

[[sweep.vote_timings]]
early = 0.80
mid = 0.10
```

Parse as:
```python
from backtesting.data.factory import VoteTimingConfig

raw_timings = sweep.get('vote_timings', None)
vote_timings = None
if raw_timings:
    vote_timings = [VoteTimingConfig(early=t['early'], mid=t['mid']) for t in raw_timings]

return SweepConfig(
    ...,
    vote_timings=vote_timings,
)
```

### Pattern 4: Import placement in sweep.py

`VoteTimingConfig` is currently imported only in `factory.py`. It is re-exported from `backtesting.data.__init__`. The sweep module uses deferred imports inside `_run_cell()` to avoid circular imports, but `VoteTimingConfig` is only needed at module level for type annotations on `SweepConfig` and `SweepCell`. Add it as a top-level import:

```python
from backtesting.data.factory import VoteTimingConfig
```

This is safe because `sweep.py` already imports `AllocationDistribution` from `backtesting.data.budget` at the top level (line 31). `VoteTimingConfig` lives in `backtesting.data.factory` which is a leaf module (no circular dependency risk with sweep.py).

### Anti-Patterns to Avoid

- **Modifying `generate_scenario()` signature:** It already accepts `vote_timing: VoteTimingConfig | None = None`. Do not touch it.
- **Modifying `factory.py` or `VoteTimingConfig`:** Both are already correct. Wiring only goes in `sweep.py`.
- **Adding vote_timing to the deferred import block inside `_run_cell()`:** `VoteTimingConfig` is only needed for the type annotation, not at runtime inside _run_cell — the `kwargs['vote_timing']` assignment works with any value. Top-level import is correct.
- **Using a string serialization axis:** Do not convert `VoteTimingConfig` to a string for the sweep axis; use the object directly (same as `mc_dist`).
- **Making vote_timings required in TOML:** Must be optional with `None` default for backward compatibility. Existing TOML configs that omit it must still work.

## Common Pitfalls

### Pitfall 1: Forgetting the [None] sentinel in _enumerate_cells

**What goes wrong:** If `config.vote_timings` is `None` and no sentinel `[None]` is added, `itertools.product` receives `None` as an iterable and raises `TypeError: 'NoneType' object is not iterable`.

**Why it happens:** `itertools.product` requires iterable arguments. `None` is not iterable.

**How to avoid:** Always write `vote_timing_values = config.vote_timings if config.vote_timings else [None]` — exactly as the mc_dist pattern does on line 124.

**Warning signs:** `TypeError` at sweep enumeration time when `vote_timings` is not set.

### Pitfall 2: Cell count explosion in tests

**What goes wrong:** Adding `vote_timings=[t1, t2]` to an existing test config doubles the cell count. Tests that assert exact row counts (`assert len(cells) == 12`) will fail.

**Why it happens:** The new axis multiplies with all existing axes: 2 curve_types × 3 alphas × 1 lock × 2 strategies × 2 vote_timings = 24 cells, not 12.

**How to avoid:** Tests for the vote_timing axis should use configs with 1 value on each other axis (or scope vote_timing tests separately from the existing cartesian product tests). The existing tests that don't set `vote_timings` should be unaffected since `None` resolves to `[None]` which adds a ×1 factor.

**Warning signs:** Existing `test_swep01_cartesian_product` and `test_swep03_multi_cell_sweep` fail with count mismatches.

### Pitfall 3: Schema mismatch between _make_failed_row and _run_cell return dict

**What goes wrong:** If `_make_failed_row` adds `vote_timing_label` but `_run_cell` return dict does not (or vice versa), `pd.DataFrame(rows)` will have NaN-filled columns for one path, causing silent schema divergence.

**Why it happens:** Both code paths feed into the same `rows` list. The DataFrame must have consistent columns.

**How to avoid:** Add `vote_timing_label` to both the `_make_failed_row` dict and the `_run_cell` return dict in the same PR.

**Warning signs:** Pandas `FutureWarning` about mixed types; test asserting expected columns fails.

### Pitfall 4: VoteTimingConfig import at wrong scope

**What goes wrong:** Placing `from backtesting.data.factory import VoteTimingConfig` inside `_run_cell()` (the deferred import block) is unnecessary and signals misunderstanding. The type is needed for `SweepConfig` and `SweepCell` field annotations at module load time, not inside the worker function.

**Why it happens:** Confusion between why mc_dist imports are deferred (circular imports from `generate_scenario` depending on cadCAD) vs why VoteTimingConfig import is not at risk.

**How to avoid:** Add `VoteTimingConfig` to the top-level imports in sweep.py, next to the existing `AllocationDistribution` import.
